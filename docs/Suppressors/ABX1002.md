# ABX1002 - Suppresses nullability warnings inside EF Core LINQ queries

This suppressor can contextually suppress nullability warnings inside EF Core queries.
This works because EF Core guarantees nullability handing when transforming the expressions to DB calls.

(For more information refer to the EF Core documentation [here][Link_EFCoreReference].)

### How the suppressor works

This suppressor addresses this.
The suppressor checks if a LINQ query is originated from a [DbSet][Link_DbSet] and also a [DbContext][Link_DbContext].
If those checks succeed the suppressor contextually suppresses all nullability warnings originated from the LINQ query parameter.
Nullability warnings from captured variables are not suppressed.

Example:
```csharp
var entity = db.Entities
    .Where(x => x.OptionalRelation.Name == "example")
    .First();
```

Normally `x.OptionalRelation.Name` would raise [CS8602][Link_PossibleDereferenceOfNull], because the relation is optional and the property is nullable.
However the suppressor can prove, that the query is a EF Core query and therefore nullability warnings can be suppressed.

## Configuration

```ini
# Enable the suppressor
# default: false
dotnet_code_quality.ABX1002.enabled = true

# Disables the prove logic for DbSet and DbContext and assumes all IQueryable are EF Core queries
# default: false
dotnet_code_quality.ABX1002.assume_all_queries_are_efcore_queries = true
```
```xml
<PropertyGroup>
  <AbaddaxRoslynAnalyzersABX1002Enabled>true</AbaddaxRoslynAnalyzersABX1002Enabled>
  <AbaddaxRoslynAnalyzersABX1002AssumeAllQueriesAreEfCoreQueries>true</AbaddaxRoslynAnalyzersABX1002AssumeAllQueriesAreEfCoreQueries>
</PropertyGroup>
```
