# ABX1001 - Suppresses nullability warnings for [MaybeNull] navigation property when using EF Core

This suppressor can contextually suppress nullability warnings for included required navigation properties marked with
[[MaybeNull]][Link_MaybeNullAttribute] when using EF Core.

### Problem

When using EF Core, required navigation properties can still be null, when not including them in the query.
This can lead to unexpected [NullReferenceException][Link_NullReferenceException] without compiler warnings.

### How the suppressor works

This suppressor addresses this.
For it to work, the navigation property must be marked with [[MaybeNull]][Link_MaybeNullAttribute] like this:

```csharp
public class User
{
    public uint Uid { get; set; }
    public string Name { get; set; } = "";
}
public class UserProfile
{
    public uint UserUid { get; set; }
    [MaybeNull]
    public User User { get; set; }
}
```

Now the suppressor can contextually suppress nullability warnings by analyzing the query:

```csharp
var profile = db.UserProfiles
    .AsNoTracking()
    .Include(x => x.User)
    .First();
var name = profile.User.Name;
```

Normally `profile.User` would raise [CS8602][Link_PossibleDereferenceOfNull], because we marked the property with [[MaybeNull]][Link_MaybeNullAttribute].
However the suppressor can prove, that `User` is included in the query and can therefore suppress the nullability warnings.

(Without [[MaybeNull]][Link_MaybeNullAttribute] the compiler would raise [CS8618][Link_NonNullableReferenceNotInitialized] directly in the `UserProfile`-class definition,
because the property is not assigned a none `null` value when exiting the constructor. 
A common pattern is to use `= null!` as the default value, however this then risks unexpected [NullReferenceException][Link_NullReferenceException] without compiler warnings when forgetting to include the property in the query.)

The suppressor can also track across assignments like so:
```csharp
var profile = db.UserProfiles
    .AsNoTracking()
    .Include(x => x.User)
    .First();
var user = profile.User
var name = user.Name; // Still suppressed
```

## Configuration

```ini
# Enable the suppressor
# default: false
dotnet_code_quality.ABX1001.enabled = true
```
```xml
<PropertyGroup>
  <AbaddaxRoslynAnalyzersABX1001Enabled>true</AbaddaxRoslynAnalyzersABX1001Enabled>
</PropertyGroup>
```

The suppressor also supports customization via attributes.

For this install the NuGet package [Abaddax.Roslyn.Analyzers.Attributes](https://www.nuget.org/packages/Abaddax.Roslyn.Analyzers.Attributes/).

### [EfCorePropertyIncludedAttribute](./../../Abaddax.Roslyn.Analyzers.Attributes/EfCorePropertyIncludedAttribute.cs)

This attribute can be used to tell the suppressor that a function guarantees the include of a specific property in the query or in the returned object.
```csharp
[return: EfCorePropertyIncluded(nameof(UserProfile.User))]
public IQueryable<UserProfile> IncludeUser(this IQueryable<UserProfile> query)
{ 
    ...
}

[return: EfCorePropertyIncluded(nameof(UserProfile.User))]
public UserProfile GetUserProfile(uint uid)
{  
    ...
}
public bool TryGetUserProfile(uint uid,
    [NotNullWhen(true)]
    [EfCorePropertyIncluded(nameof(UserProfile.User))]
    out UserProfile? userProfile)
{ 
    ...
}
```

### [ForwardedParameterAttribute](./../../Abaddax.Roslyn.Analyzers.Attributes/ForwardedParameterAttribute.cs)

This attribute can be used to customize the tracking logic and allow it to track lambda-style parameters:
```
public void DoSomething(UserProfile profile,
    [ForwardedParameter(nameof(profile))] Action<UserProfile> action)
{ 
    ...
}
```
Which then allows the following:
```
var profile = db.UserProfiles
    .AsNoTracking()
    .Include(x => x.User)
    .First();

DoSomething(userProfile, (p) =>
{
    var name = p.User.Name; //Still suppressed (because the tracker knowns that 'p' is the forwarded 'userProfile')
});
```
